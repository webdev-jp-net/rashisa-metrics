# 画面構成と挙動

文体解析レポートのページ（`/<seriesKey>/`）における、上から下への構造と、タブ切替・URLハッシュ同期・検索時自動展開・スクロール挙動と、ルート（`/`）のシリーズの一覧を定義する。レポートのページタイトル・リード文はパスのシリーズ（microCMSの`series`の`siteTitle`・`siteLead`）から、ヒーローの導入文は同じシリーズの`description`から読む。以下のページ構造は、そのシリーズの許可リストにあるGoogleアカウントでログインした閲覧者に表示する。許可リストが空のシリーズは、ログインしていない閲覧者にも表示する。それ以外の閲覧者にはログイン促し画面（後述）を表示する。

## ページ構造

| 区画         | id                | 内容                                                                                 |
| ------------ | ----------------- | ------------------------------------------------------------------------------------ |
| ヒーロー     | `#top`            | タイトル(`h1`)・リード文・導入文・「どのように解析？」リンク                         |
| 解析導入     | `#analysis-intro` | 左カラム：導入文2段落＋「レポートをみる」リンク。右カラム：観点定義カード4枚（単列） |
| レポート本体 | `#report-view`    | スティッキーなスコープ切替ナビ＋全スコープ（全体＋個別スコープ）のパネル             |

ヒーローと解析導入はそれぞれ`min-height:100dvh`のフルビューポート高セクションで、内容は縦方向中央配置。レポート本体もスクロールスナップ対象で、吸着位置はその上端（スコープナビの位置）。

### ヒーロー

`h1`にサイトタイトル、直下に`.lead`でリード文、続けて導入文。導入文はシリーズの`description`（リンクだけを許可したリッチテキスト）をサニタイズしたHTMLで、空なら`src/lib/api/microcms.ts`の初期値（`DEFAULT_DESCRIPTION`）を出す。導入文の下、左寄せ（`HeroSection`の`.box`内、`align-self:flex-start`）に「どのように解析？」の`.hint`リンク（`href="#analysis-intro"`）。

### 解析導入

2カラムグリッド（`IntroSection`の`.columns`）。左カラム（`.copy`）は段落2つ「文体を解析する4つの観点のデータを抽出し、数値的に近づけた場合の実例を提案しています。」「データ由来の指標には、読み比べによる実感由来の判断とは違った客観性や再現性があります。編集のヒントとしてお役立てください。」（2文目は`<br>`で改行）に続けて「レポートをみる」の`.hint`リンク（`href="#report-view"`）。右カラムは観点定義カード4枚（LSM・文末表現・敬語の密度・文・段落の長さ、各カードの内容はデザイン規約の軸定義カード節を参照）。

## シリーズの一覧

ルート（`/`）の画面（`SeriesIndex`）。ログイン促し画面と同じ`.box`／`.copy`の構成（`h1`＋`.lead`）・上下中央寄せ（`min-height:100dvh`）で、`h1`に「RASHISAメトリクス」、`.lead`に「「らしさ」を数値的・客観的に観測する」、続けて段落「お手本と編集対象の文章を比較して、文体を解析する4つの観点のデータを抽出し数値的に近づけた場合の実例を提案しています。」（「抽出し」の後を`<br>`で改行）を出す。ここまではログインの有無にかかわらず同じ。その下に次の3つをこの順に出す。

| 要素                 | 表示                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| シリーズのリスト     | 小見出し「レポート：」（`h2`、見た目は`h3`相当）に続く、その人が閲覧できるシリーズのシリーズ名（`series.siteTitle`）のリンクの箇条書き。リンク先は`/<seriesKey>/`。未ログインなら許可リストが空のシリーズ、ログイン済みならそれに加えて許可リストにあるシリーズ。1件も無ければ小見出しごと出さない。全体スコープの箇条書きの提案（`TotalProposal`の`.list`）と同じ、先頭に横線の印を付けた箇条書き。文字はサイズ`--t-lg`・行送り`--lh-lg` |
| 注釈                 | 「一部のレポートは限定公開です。権限のあるアカウントでログインすると閲覧できます。」（サイズ`--t-sm`・色`--ink-desc`）。ログインの有無にかかわらず同じ                                                                                                                                                                                                                                                                                    |
| ログイン・ログアウト | 未ログインなら「ログインする」ボタン（`signIn('google')`、ログイン後はルートへ戻る）、ログイン済みなら「ログアウトする」ボタン（`signOut()`）。secondaryのボタン（[デザイン規約のボタン](../design-system.md#ボタン)）                                                                                                                                                                                                                    |

シリーズ名がシリーズどうしで同じでもそのまま並べる。

## ログイン促し画面

許可されたGoogleアカウントでログインしていない場合、上記のページ構造の代わりにこの画面（`LoginPrompt`）を表示する（[NextAuth認証仕様](../backend/next-auth.md)参照）。`<main>`直下に`.box`（サイトタイトル・リード文・メッセージ・ボタン）だけを配置する単純な構造で、`HeroSection`と同じ`.box`／`.copy`の構成（`h1`＋`.lead`）・上下中央寄せ（`min-height:100dvh`）を使う。スコープナビ等ページ構造の他の要素は持たない。ボタンはsecondaryのボタン（[デザイン規約のボタン](../design-system.md#ボタン)）。

| 状態         | 表示条件                         | メッセージ（段落）                                                                                                                                         | ボタン             | ボタン操作         |
| ------------ | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ | ------------------ |
| `signedOut`  | 未ログイン                       | 「このレポートは限定公開です。権限のあるアカウントでログインすると閲覧できます。」                                                                         | 「ログインする」   | `signIn('google')` |
| `notAllowed` | ログイン済みだが許可リストに無い | 「このレポートは限定公開です。権限のあるアカウントでログインすると閲覧できます。」「閲覧権限がないアカウントでログインしているため、ご覧いただけません。」 | 「ログアウトする」 | `signOut()`        |

## スコープ一覧とid

全体スコープ＋個別スコープ。パネルidは`report-{key}`、対応するタブのid（ボタン要素）は`tab-report-{key}`。

| key         | 表示名                        | パネルid           | タブid                 |
| ----------- | ----------------------------- | ------------------ | ---------------------- |
| `total`     | 全体                          | `report-total`     | `tab-report-total`     |
| `{scopeId}` | シリーズの`scopeList[].label` | `report-{scopeId}` | `tab-report-{scopeId}` |

個別スコープの件数・id・表示名はパスのシリーズの`scopeList`（microCMSの`series`）から読む値で、コードに直書きしない。件数は固定しない。

## スコープパネルの内容

各スコープパネル（`ScopePanel`の`.panel`）の中に`.body`があり、その中が提案パネル（全体は`TotalProposal`の`.proposal`、個別スコープは`ScopeProposal`の`.panel`）＋`<hr>`＋`.analysis`（分析パネル、見出し「分析データ」）の順で構成される。

### 全体スコープ

`.proposal`内に次を上から順に配置する。

1. **概要リード文**（`TotalProposal`の`.summary`）：3段落。
   - 1段落目：`{お手本メディア名}で公開中の記事をお手本とし、{編集対象メディア名}が{お手本メディア名}らしい文体かどうか分析しました。`（お手本メディア名・編集対象メディア名はパスのシリーズの`modelLabel`・`editedLabel`（microCMSの`series`）から読む。UI文言・凡例・表見出しのnote／書籍表記はすべてこの表示名から組み立て、コードに媒体名を直書きしない）
   - 2段落目：全体LSM値に応じた定性文。LSM値が「高い一致度」のしきい値（0.85）以上なら「全体を総合的に解析すると、言葉の使い方の類似度を図るLSMが{値}で、高い一致度です。」、未満なら「〜LSMは{値}です。」
   - 3段落目：「章ごとに区切って分析した場合は、ばらつきがあり」に続けて改行し、最もLSMが低いスコープ・高いスコープの名前と値を「最も一致していなかったのが{スコープ名}の{値}、最も一致していたのが{スコープ名}の{値}でした。」
2. **箇条書きの提案**（`.suggestions`）：見出し「指標を基準に文体を近づける提案：」の下に、全体行で基準超過した項目を`{観点} - {項目名}を{増やす/減らす/長くする/短くする}調整`の形で列挙する。項目名は文法語・文末・敬語は項目名そのもの（例：「文末表現 - です・ますを増やす調整」）、文長・段落長は「{観点}・{項目}」の形（例：「文・段落の長さ - 文長・平均を短くする調整」）。LSM平均のみ「LSM - 全体の類似度を上げる調整」の固定文言。方向は差分の符号から自動で決まる（文長・段落長は値が正＝編集対象がお手本より長いなら短くする、それ以外は値が正＝編集対象がお手本より多いなら減らす）
3. **比較テーブル**（`.evidence`）：後述

### 個別スコープ

`ScopeProposal`の`.panel`内に「概要」＋再測定テーブル＋diffボックスを配置する。概要部分（`.summary`）は次の2要素。

1. `data.metricList`のいずれかがstandout（`target === true`）である場合「値が離れている指標で、ちがいを緩和する提案です。」、1件もない場合「今回の調整対象はありません。」の1文
2. **平均LSMの提案前後**（`LsmBeforeAfter`の`.summary`）：「平均LSM」ラベル＋変更前の数値、矢印アイコン、「提案後 平均LSM」ラベル＋変更後の数値を横並びで表示

概要部分に続けて次を配置する。

- **再測定テーブル**：デザイン規約の`.metrics`節を参照。行見出しはスコープ（番号バッジ付き）と項目の2段、列は既存テキスト／→／調整提案／参考とするnoteの指標
- **diffボックス**：後述

`revisionStatus`が`complete`でないスコープは、その提案パネルを空にする。`version`が`chapter-revision-4`でないファイルは版名を示すエラーで描画を止める。

### 比較テーブル

全体行＋個別スコープ行の一覧テーブル。列は「スコープ名」「差のある指標」（セルは「N / 27」の形）「文字数」＋各指標列（LSM平均、文法語10、文末7、敬語4、文長3、段落長3の計28列、うち敬語「合計」列は件数に含めない）。

- スコープ名セルはボタン。クリックするとスコープ切替ナビの同じスコープのタブ（`tab-report-{key}`）へクリックを転送し、そのスコープパネルを開く。テーブル自身は別の切替状態を持たない
- 基準を超えたセルは強調表示（デザイン規約の`.standout`）。強調セルの基準は[判定規則](../../analysis/overview-policy.md)を参照
- **フィルターボタン**（`.controls`、`aria-pressed`で選択状態を管理）：「主要項目」（既定選択、LSM平均・文末の「です・ます」「終助詞止め」・敬語の「丁寧語」「謙譲語」・文長段落長の全6項目のみ表示）、`01 LSM 類似度`（LSM平均＋文法語10項目）、`02 文末表現`（文末7項目）、`03 敬語の密度`（敬語4項目）、`04 文・段落の長さ`（文長3＋段落長3）、「全項目」（全28列）。番号バッジは観点タブと同じ`NumberBadge`コンポーネントで表示
- 各セルは`title`属性でその値の根拠を示す：LSM平均セルは「Pennebaker(2011)のhigh synchrony目安（{しきい値}以上）未満」、集計対象（`counted`）の列は「{お手本メディア名} {お手本の値}／差の許容幅 ±{許容幅}{単位}（暫定）」、非集計列は「参考値・件数に含めません」。「差のある指標」セルの`title`には、その行で基準超過した項目名の一覧（該当なしなら「該当なし」）が入る
- 表の下に注記文を2つ表示する：「お手本との差が一定の基準を超えている箇所をハイライトしています。」「全体は全文の集計値で、章別値の単純平均ではありません。文字数は分析に用いた抽出データの文字数です。表示は丸めています。」

## 分析パネル

各スコープパネルの`.analysis`内、見出し「分析データ」（`h2`）の下に観点タブ（`role=tablist`、ラベル「観点」）＋4つのタブパネルを配置する。

| 観点キー     | タブ表示名     | 番号バッジ |
| ------------ | -------------- | ---------- |
| `lsm`        | LSM 類似度     | 01         |
| `endings`    | 文末表現       | 02         |
| `politeness` | 敬語の密度     | 03         |
| `length`     | 文・段落の長さ | 04         |

観点タブのパネルid規則は`report-{scope}-{axis}`（例：`report-total-lsm`、`report-0-endings`）。パネル内容：

- **LSM**：カテゴリ別LSM図（デザイン規約の「LSMスケールバー」参照）＋所見テキスト
- **文末表現**：文末表現の割合のペア棒グラフ（全体スコープは0〜60%、個別スコープは0〜80%）＋所見テキスト
- **敬語の密度**：敬語密度（形態素1,000あたり）のペア棒グラフ（全体0〜40‰、個別0〜50‰）＋所見テキスト
- **文・段落の長さ**：一文の長さ分布要約のペア棒グラフ（全体0〜80字、個別0〜80字）＋段落の長さ分布要約のペア棒グラフ（全体0〜160字、個別0〜200字）＋所見テキスト

所見テキスト（見出し＋段落）は`data/<seriesKey>/report/finding_texts.json`の該当スコープ・観点のエントリをそのまま描画する（分析パネル自体はこのJSONを読むだけで、原稿の再計測では更新されない）。観点の定義文（軸定義カード）は解析導入セクションに1度だけ表示し、各分析パネル内では繰り返さない。

## タブのARIA・キーボード操作

スコープタブ・観点タブはいずれも同一の実装に従う。

- タブ列は`role="tablist"`＋`aria-label`（スコープタブは「スコープ」、観点タブは「観点」）。各タブは`role="tab"`・`id="tab-{panelId}"`・`aria-controls="{panelId}"`
- 選択中タブは`aria-selected="true"`・`tabindex="0"`。非選択タブは`aria-selected="false"`・`tabindex="-1"`
- 対応するパネルは`role="tabpanel"`・`aria-labelledby="tab-{panelId}"`。サーバー描画時は非選択パネルに真偽値の`hidden`（値なし）を出力し、ハイドレーション後は`useTabPanel`フック（`src/app/_parts/useReport.ts`）のeffectが非選択パネルへ`hidden="until-found"`を`setAttribute`する。選択されると同じeffectが`hidden`属性を外す
- キーボード：フォーカスのあるタブで矢印キー右／左（`ArrowRight`/`ArrowLeft`）を押すと、同じタブリスト内の次／前のタブへフォーカス移動し、そのタブを選択状態にする（末尾から先頭・先頭から末尾へは循環）
- クリックでもタブを選択状態にする

## URLハッシュ同期

スコープタブ列（`ScopeNav`の`.list`）のみ、選択状態の変更をURLハッシュと同期する。観点タブ・比較テーブルのフィルターボタンはハッシュと同期しない。

- スコープタブをクリック（またはキーボードで選択）すると、`history.pushState`で`location.hash`を選択したパネルのid（例：`#report-0`）に更新する（既に同じハッシュなら更新しない）
- ブラウザの戻る・進む（`popstate`イベント）で、その時点の`location.hash`に一致するタブを選択状態にする
- ページ読み込み時にも同じ同期処理を1回実行する。ハッシュがどのスコープにも一致しない、またはハッシュがない場合は先頭のタブ（`report-total`、全体スコープ）を開く
- ヒーロー（`#top`）と解析導入（`#analysis-intro`）へのリンクは通常のアンカーリンクであり、タブの仕組みとは独立してブラウザ標準の戻る・進む履歴に含まれる

## ページ内検索との連動

非選択のタブパネルは（ハイドレーション後）`hidden="until-found"`属性で保持され、レイアウト上は非表示だがDOMには存在し続ける。ブラウザのページ内検索（find-in-page）がこの属性を持つ要素内のテキストに一致すると、ブラウザは自動的にその要素の`beforematch`イベントを発火して`hidden`を解除する。この画面では各タブパネルの`beforematch`イベントを監視し、発火したら対応するタブを選択状態にする（このときはURLハッシュを更新しない）。これにより、検索でヒットしたスコープ・観点のパネルが自動的に開いた状態になる。

## スティッキーなスコープナビ

レポート本体のスコープ切替ナビ（サイトタイトルリンク＋スコープタブ列）は`position:sticky;top:0`で、スクロールしてもビューポート上端に留まる。stuck状態の見た目は[デザイン規約のスティッキーなスコープ切替ナビ](../design-system.md#スティッキーなスコープ切替ナビ)を参照。

- サイトタイトルリンク「文体解析レポート」は`#top`（ヒーロー）へのアンカーで、ページ先頭へ戻る導線を兼ねる。専用の「トップへ戻る」ボタンは別途持たない

## スムーズスクロール

ページ全体に`scroll-behavior:smooth`が指定されており、「どのように解析？」「レポートをみる」の`.hint`リンクと、通常のアンカーリンク（`#top`・`#analysis-intro`）はスムーズスクロールで移動する。比較テーブルのスコープ名ボタンはタブを開くだけでスクロールしない。

## diffボックスの折りたたみ

各diffボックスは初期状態で、変更のない行が3行（前後の文脈）を超える区間を折りたたみ行として表示する。折りたたみ行の見た目は[デザイン規約の折りたたみ制御](../design-system.md#折りたたみ制御)を参照。

- 折りたたみ行をクリックすると、隠れている行のうち先頭10行を表示し、残りがあれば「残りN行を表示」に更新する。残り0行になった時点で折りたたみ行自体を除去する
- diffボックスのヘッダーボタン（「すべて展開」／「すべて折りたたむ」の切替、`aria-pressed`で状態管理）をクリックすると、展開状態では全ての折りたたみ行を一括展開し、収納状態では`tbody`の内容を初期状態（折りたたみ済み）に戻す

## IntersectionObserverによる挙動

| 監視対象                                                      | 目的                                   | 挙動                                                                                                                                                                                             |
| ------------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| スコープ切替ナビ本体                                          | stuck状態の検知                        | `threshold:[0,1]`・`rootMargin:'-1px 0px 0px 0px'`で観測し、`intersectionRatio<1`かつ`boundingClientRect.top<=0`のときstuck状態にする                                                            |
| 各`.chart`（ペア棒グラフ・LSM図）                             | グラフのin-viewアニメーション起動      | `threshold:.2`で観測し、一度でも交差したらin-view状態にしてバーの伸長アニメーションを起動、以降は監視を止める（1回限り）                                                                         |
| 各ビューポートセクション（`view-timeline`未対応ブラウザのみ） | スクロール位置に応じたフェード量の算出 | `boundingClientRect`から算出したフェード量（0〜1）を要素へ反映する。対応ブラウザではCSSのスクロール駆動アニメーション（`animation-timeline:view()`）に委譲し、このIntersectionObserverは使わない |

## フォントのフォールバック

Google Fontsが未接続・オフラインで読み込めない場合のフォールバックは[デザイン規約の書体](../design-system.md#書体)を参照。

## favicon

32×32pxのPNG画像をbase64データURIとして`<link rel="icon">`タグに直接埋め込む。外部ファイルへの参照は持たない。

画面幅による構成の切り替え（レスポンシブ表示）はない。幅方向のブレークポイントは[デザイン規約](../design-system.md)のとおり定義しない。

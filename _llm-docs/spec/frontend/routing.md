# ルーティング仕様

## ページ構成

Next.js App Router（`src/app`）を利用した構成。レポート本体はシリーズごとのパスで開く1ページで、ルートは閲覧できるシリーズの一覧。

## ルート構成

| ルート          | 説明                                                                                                                                                                                                                                    |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`             | シリーズの一覧（`SeriesIndex`）。その人が閲覧できるシリーズ（許可リストが空のシリーズと、ログインしていれば許可リストにあるシリーズ）だけをmicroCMSから取って並べ、その下にログインまたはログアウトのボタンを出す                       |
| `/<seriesKey>/` | レポート本体。Server Componentの`[seriesKey]/page.tsx`がパスの`seriesKey`のシリーズとその表示材料をmicroCMSから取得し、許可リスト判定（[NextAuth認証仕様](../backend/next-auth.md)）を経て描画する。該当するシリーズが無ければ404を返す |
| `/api/auth/*`   | NextAuthの認証API Route（`route.ts`が`GET`・`POST`を処理する）                                                                                                                                                                          |

非許可・未ログインの場合、`/<seriesKey>/`は`LoginPrompt`を描画する。ミドルウェアによる一括保護は行わない。

## ハッシュフラグメント

スコープ切替・アンカーリンクはURLハッシュと同期する。ブラウザの戻る・進むで移動できる。

| ハッシュ            | 意味                                                                                         |
| ------------------- | -------------------------------------------------------------------------------------------- |
| `#top`              | hero（タイトル・リード・導入文）の先頭                                                       |
| `#analysis-intro`   | 導入文と観点カード4枚のセクション先頭                                                        |
| `#report-view`      | レポート本体（スコープ切替ナビと全スコープの内容をまとめた領域）の先頭。ナビの位置に吸着する |
| `#report-total`     | 全体スコープパネル                                                                           |
| `#report-{scopeId}` | 個別スコープパネル。`scopeId`はパスのシリーズの`scopeList[].scopeId`                         |

ハッシュが該当なし・空のときは全体スコープを開く。スコープ切替ボタンのクリックでハッシュを更新し、非表示パネルは`hidden="until-found"`属性で保持する。

## ディレクトリ構造

ルーティングに関わる`src/app`配下の構造。全体は[プロジェクト概要のディレクトリ一覧](../../project.md#ディレクトリ一覧)を参照。

- `layout.tsx`: ルートlayout
- `page.tsx`: ルート（シリーズの一覧）のServer Component
- `[seriesKey]/page.tsx`: パスのシリーズのデータ読込と派生値の組み立てを行うServer Component
- `_parts/view.tsx`: `'use client'`。表示のみ
- `_parts/useReport.ts`: スコープ・観点タブの状態管理とURLハッシュ同期
- `_parts/page.module.scss`: ページ固有のスタイル
- `_parts/components/`: このページ専用で繰り返し使う部品（parts-component構造）

## エラーハンドリング

データの欠落・不正はレンダリングを失敗させ、欠けているものを名指しするエラーを投げる。固定文へのフォールバックはしない。パスの`seriesKey`のシリーズがmicroCMSに無ければ、ログイン判定より前に404を返す。許可された後は、そのシリーズの`report`が全体スコープまたは`scopeList`のいずれかで欠けている、または総評が4観点そろっていなければ止まる。

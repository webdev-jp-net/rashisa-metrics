# 計測仕様

4観点・26指標の計測は`src/lib/text/`（入力整形・文書の前処理）・`src/lib/morph/`（形態素解析アダプタ）・`src/lib/metrics/`（LSM・文末表現・敬語密度・文長分布・句読点・n-gram）に実装する。計測結果は`stylometricProfile`形式のJSONとして`data/<seriesKey>/profiles/`配下に保存する。[判定規則](./overview-policy.md)（`src/lib/policy/`）は、このプロファイルから導出した比較データ（`comparison_data*.json`相当の値）だけを入力に使う。[章単位編集案](./revision-workflow.md)（`src/lib/revision/`）はプロファイルに加え、原稿本文・`overview_criteria.json`・該当スコープの`comparison_dataN.json`・実例集・書き方シート・LSM/敬語辞書のYAML一式も読み、`measureDetail`で改稿後の文章を再計測する。

## 入力整形

計測対象の文章は、計測前に個人情報・識別子を除去した状態（`clean`）にする。除去は2段階。

1. 個人名・固有名詞の用語リスト（対象媒体ごとに定義。編集対象媒体の原稿では著者本人・登場する実在人物の名前）を、長い語から順に単純文字列置換で除去する。
2. 汎用パターン`PATTERN_LIST`を正規表現で除去する。パターンは順に、メールアドレス、URL、電話番号、0始まり10〜11桁の数字列、郵便番号、12〜19桁の連続数字（クレジットカード番号相当）、住所（2〜3字の漢字＋「都道府県」のいずれか＋60字以内の非空白・非句読点文字列）、ファイルパス（`/Users/`始まり）、`[...]`で囲まれた角括弧内容。

住所パターンは「都道府県」の1文字を含む語（例：「高速道路」の「道」）に誤反応することがある。誤検出が判明した具体的な文字列は例外リストに登録し、該当箇所だけパターン除去の対象から外す。例外リストは対象媒体ごとに保持する。

除去結果は空文字に置換する（用語・PATTERN_LIST共通）。この除去後の文字列が計測対象の`clean`であり、LSM・敬語・文末表現・長さ分布などすべての数値はこの文字列から算出する。

### 表示用マスキング

レポートの差分表示（diff）など、原稿の地の文をそのまま画面に出す箇所では、計測用の`clean`とは別に表示用の`visible`を作る。

- 個人名・固有名詞の用語は種別ごとの伏せ字（例：著者名は「［著者名］」、その他人物名は「［人物名］」）に置換する。除去（空文字化）ではなく伏せ字化。
- 汎用パターンのうち、角括弧パターンを除く残り全部（メール・URL・電話番号・数字列・郵便番号・カード番号相当・住所・ファイルパス）を「［個人情報］」に置換する。角括弧パターンは表示マスキングの対象に含めない。
- 例外リストに登録された文字列はどちらのパターンにも一致していてもそのまま残す。

`visible`は表示にのみ使い、計測には使わない。計測とマスク表示は同じ原文から独立に導出し、表示側の加工が計測値に混ざらないようにする。

## 文書の前処理

原資料ディレクトリの1文書（お手本の1記事、編集対象の1スコープ）の全文を前処理する処理（`chapterSource`）は次の手順で行う。

1. 文書ファイルの全文を行配列として読む（改行は`\n`・`\r\n`・`\r`のいずれも扱う）。
2. 各行について、`---`のみからなる区切り線の行は除外し、それ以外の行は見出し記号（`^#{1,6} `）を除去する（見出しの文字テキストは残す）。
3. 残った行の先頭・末尾にある空行を取り除く。
4. 残りを改行で連結し、前後の空白を除去した文字列を前処理後の本文とする。あわせて、採用した各行の元ファイルの行番号（1-based、そのファイル内での行番号）を順序付きで保持する（本文内オフセットから元ファイルの行へ逆引きするために使う）。

両媒体に同じ前処理を適用する（お手本記事に見出し行・区切り線は無いため実質そのまま通る）。この前処理結果（本文文字列＋行番号列）が、計測入力・変更案の`before`/`after`照合・原資料ファイルへの書き戻しの共通の基準になる。前処理ルール（見出し記号除去・`---`除去・空行トリム）を変えた場合、保存済みプロファイルの計測値とは一致しなくなるため、影響する文書をすべて再計測する。

## 段落・文の分割

- **段落**：空行（`\n`の後に空白のみの行が1行以上続く）で区切る。連続する空行はひとつの区切りとして扱う。区切られた各断片の前後空白を除いた文字列が段落。空段落は除外する。
- **文（記事系文書）**：段落ごとに「。」で分割し、前後空白を除いた非空文字列を文とする。区切り文字自体は文に含めない。この規則は文長分布・文法語比率などのLSM計測に使う。
- **文末表現分類専用の文境界**：文末表現（7ラベル）の分類だけは別の境界規則を使う。対象単位（記事なら段落、メッセージ系文書ならメッセージ全体）を「。」「！」「!」「？」「?」「改行」のいずれかで分割し、前後空白を除いた非空文字列を文とする。この境界は句点だけに頼らず改行も文区切りとして扱う点で、上記のLSM用の文分割と異なる。

## トークナイザ契約

形態素解析器は`lindera-wasm-unidic-nodejs`（UniDic辞書、WASM実装、同期API）を使う。`src/lib/morph/`のアダプタを介して呼び出し、各トークンは次のキーを持つオブジェクトとして統一する。

| キー       | 内容                                                                                                                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `surface`  | 表層形                                                                                                                                                                                         |
| `pos1`     | 品詞第1階層（例：助詞、動詞、助動詞）。解析結果の`details[0]`                                                                                                                                  |
| `pos2`     | 品詞第2階層（例：格助詞、終助詞。第1階層のみのカテゴリでは未使用）。解析結果の`details[1]`（`*`のときは空文字列）                                                                              |
| `lemma`    | 辞書形（見出し語）。解析結果の`details[10]`（語彙素の書字形。orthographic_base_form）を使い、値がなければ`details[7]`（語彙素の代表表記。lexeme）、それもなければ`surface`にフォールバックする |
| `document` | そのトークンが属する文書（原稿ならスコープ、比較対象ならお手本記事）を一意に識別する値。複数文書を連結してトークナイズした際に、境界をまたいで誤判定しないために使う                           |

分割粒度はUniDicの短単位に従う。LSMカテゴリの`posFilter`はUniDicの品詞体系（pos1/pos2）で定義する。

## LSMカテゴリ

LSMカテゴリは10種。定義の正本は`config/lsm_categories.yaml`。各カテゴリはpos1/pos2によるフィルタ（`posFilter`）、表層一致の追加語彙（`extraLemmaList`）、辞書形一致の語彙（`lemmaList`）のいずれか・組み合わせで、対象トークンの添字集合を求める。

| カテゴリ                               | 判定                                                                                                                                                                                                                                 |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `caseParticles`（格助詞）              | pos1=助詞・pos2=格助詞                                                                                                                                                                                                               |
| `bindingParticles`（係助詞・とりたて） | pos1=助詞・pos2=係助詞、または表層が「だけ・しか・ばかり・まで・さえ・こそ」                                                                                                                                                         |
| `conjunctiveParticles`（接続助詞）     | pos1=助詞・pos2=接続助詞                                                                                                                                                                                                             |
| `finalParticles`（終助詞）             | pos1=助詞・pos2=終助詞                                                                                                                                                                                                               |
| `auxiliaries`（助動詞）                | pos1=助動詞                                                                                                                                                                                                                          |
| `conjunctions`（接続詞）               | pos1=接続詞                                                                                                                                                                                                                          |
| `pronouns`（代名詞）                   | pos1=代名詞                                                                                                                                                                                                                          |
| `adverbs`（副詞）                      | pos1=副詞                                                                                                                                                                                                                            |
| `negations`（否定）                    | 辞書形が「ない・ぬ・ず」（品詞をまたぐため辞書形一致。下記のモーダル否定除外を適用）                                                                                                                                                 |
| `quantifiers`（数量詞）                | 辞書形が設定済みの数量・程度語彙（「全部・全て・すべて・少し・たくさん・沢山・くらい・ぐらい・ほど・一部・半分・大体・だいたい・多く・数多く・多い・数多い・多数・大量・少量・少ない」）。「一つ」のような数そのものの表現は含まない |

1トークンが複数カテゴリの条件を満たす場合、各カテゴリで独立に判定するため重複して計上されうる（カテゴリ間の排他制御はない）。

### モーダル否定の除外

「かもしれない／かもしれません」型の推量構文に含まれる末尾の否定助動詞は、`negations`から無条件に除外する（`config/lsm_categories.yaml`の`categoryList.negations.excludeModalConstruction`の値は参照しない）。判定は次の並びをトークン列上で探索する。

1. 表層が「か」かつpos1=助詞のトークンを起点とする。
2. 直後が表層「も」・pos1=助詞。
3. その直後が辞書形「しれる」または「知れる」・pos1=動詞。
4. その直後の辞書形が「ます」なら1トークン読み飛ばす。
5. 到達したトークンがpos1=助動詞かつ辞書形が「ない・ぬ・ず」のいずれかであれば、そのトークンを`negations`の対象から除外する。

起点から4トークン目までは同一`document`に属していることを条件とする（文書境界をまたぐ誤判定を防ぐ）。この除外は、数量表現を類義語に言い換えることを「数量詞削減」と誤認しないことと対をなす運用規則で、[章単位編集案](./revision-workflow.md)の候補判定にも同じ関数を使う。

## LSMの算出

カテゴリ`c`の使用率は`p_c = カテゴリcに該当するトークン数 / 総トークン数`。総トークン数が`minTokens`（設定値。現行100）未満の文書はLSMを算出しない。

2文書間のカテゴリ別LSMは`LSM_c = 1 - |p_c(A) - p_c(B)| / (p_c(A) + p_c(B))`（分母が0のときは1とする）。全カテゴリの単純平均を平均LSMとする。この式はレポート側（`overview-policy.md`・比較データ）で使う簡易式で、両文書とも同じ`minTokens`条件を満たしていることを前提とする。

## 文末表現

文末表現は7ラベルに分類する。分類対象は「段落・文の分割」の文末表現専用の文境界で得た文。各文に対し、次のラベルを上から順に判定し、最初に一致したものを採用する。

| ラベル                            | 判定パターン（文字列末尾）                                                                               |
| --------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `desuMasu`（です・ます）          | `(です\|ます\|でした\|ました)`の後に句読点記号が0個以上                                                  |
| `daDearu`（だ・である）           | `(だ\|である\|だった)`の後に句読点記号が0個以上                                                          |
| `finalParticle`（終助詞止め）     | `(ね\|よ\|かな\|な\|わ\|の)`の後に句読点記号が0個以上                                                    |
| `symbolEnd`（記号止め）           | `！!？?…`のいずれかが1個以上連続して文末                                                                 |
| `taigenDomeOrOther`（体言止め等） | 上記に一致せず、文末が漢字・ひらがな・カタカナ・長音符のいずれか（活用語尾か体言かは区別しない簡易判定） |
| `noEnding`（文末なし）            | 上記いずれにも一致しない                                                                                 |

「句読点記号」は「。！!？?」のいずれか0個以上の連続。

### 絵文字止めの補正

対象単位（段落またはメッセージ）の末尾40文字以内に絵文字ショートコード（`:xxx:`形式）があり、かつ単位全体の末尾（前後空白除去後）が`:`で終わる場合、その単位から得た文のうち最後の1件のラベルを`emojiEnd`に上書きする。対象単位に文が1つもない場合は、単位全体を1文とみなし`emojiEnd`を単独で計上する。

### 文境界の使い分け

文末表現分類の文境界は「。」「！」「!」「？」「?」「改行」の6種である。文末表現の判定だけこの境界を使い、他の文長分布・LSM計測は「段落・文の分割」の句点のみの境界を使う。両者を混同しない。

## 敬語

敬語は丁寧度の観点で尊敬語（`sonkeigo`）・謙譲語（`kenjougo`）・丁寧語（`teineigo`）の3分類とする。定義の正本は`config/keigo_lexicon.yaml`。分類ごとに、辞書形一致リスト（`lemmaList`）と表層正規表現リスト（`surfacePatternList`）の両方でヒット数を数え、合算する。

- `sonkeigo`：「いらっしゃる・おっしゃる・なさる・下さる・召し上がる・ご覧になる」等の辞書形、および「お／ご＋1〜6字＋になる系」「お／ご＋1〜6字＋ください系」の表層パターン。助動詞「れる・られる」の尊敬用法は受身・可能と形態素上区別できないため計測対象外。
- `kenjougo`：「致す・頂く・申す・申し上げる・伺う・参る・拝見・拝借・存じる・承る・頂戴・差し上げる・お目にかかる・恐れ入る」等の辞書形、および「お／ご＋1〜6字＋する系」「させていただく系」の表層パターン。「頂く」は授受動詞用法（物をもらう）と謙譲補助動詞用法を区別せず一括計上する。
- `teineigo`：「です・ます・ございます」の辞書形、および「でございます」の表層パターン。

密度は`カテゴリ別ヒット数 / 総形態素数 × 1000`（形態素1000あたり）。3分類を単純合算したものを`politenessIndexPer1000Morph`とする。総形態素数は`totalMorphemes`として併記する。総形態素数が0の場合は1として扱い0除算を避ける。

## 長さ分布

文・段落・文書それぞれの文字数から、平均（`mean`）・中央値（`median`）・90パーセンタイル（`p90`）を算出する。値は小数第2位で丸める。空集合は3値とも0。

パーセンタイルは線形補間で求める。値の昇順配列を`v`、要素数`n`として、目標位置`k = (n - 1) × p`（`p`は0〜1の割合。中央値は0.5、90%点は0.9）を計算し、`floor(k)`と`ceil(k)`が一致すればその要素を、しなければ`v[floor(k)] + (v[ceil(k)] - v[floor(k)]) × (k - floor(k))`を返す。

## 句読点・n-gram

### 句読点

計測対象の全文書を連結した文字列に対して、以下を集計しレート化（`件数 / 総文字数`）する。

| 項目                    | 対象                                                                                     |
| ----------------------- | ---------------------------------------------------------------------------------------- |
| `kuten`                 | 「。」の出現数                                                                           |
| `touten`                | 「、」の出現数                                                                           |
| `exclamation`           | 「！」「!」の出現数                                                                      |
| `question`              | 「？」「?」の出現数                                                                      |
| `ellipsis`              | 「…」の1回以上連続、`.`の3回以上連続、「・」の2回以上連続、「。」の3回以上連続のいずれか |
| `bracketList.kagi`      | 「」の出現数                                                                             |
| `bracketList.maru`      | （）・()の出現数                                                                         |
| `bracketList.sumitsuki` | 【】の出現数                                                                             |

`linebreakPerDocument`は、文書ごとの改行数の平均（文書数で割る。レート化ではなく単純平均、小数第3位）。

### n-gram

各文書から絵文字ショートコードを除去した本文に対して、空白を除去したうえで文字3-gramを作る。全文書分を合算したカウンタから、出現数降順（同数はgram文字列の昇順）で`topFrequency`（gram・件数・レート）を出力する。対照コーパスがないため、際立った3-gram（`topDistinctive`）と特徴語彙（`vocabulary.distinctiveTermList`）は常に`null`とし、`uncomputed`に理由（`noContrastCorpus`）を記録する。

## 計測メタデータ

計測結果には次のメタデータを付与する。

| フィールド              | 内容                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------- |
| `version`               | 計測ロジックのバージョン識別子                                                              |
| `documentType`          | `article`（記事・書籍等、段落境界を尊重）または`message`（メッセージ単位）                  |
| `textState`             | `sanitized`固定（入力整形済みであることの明示）                                             |
| `paragraphRule`         | 段落分割規則の識別子                                                                        |
| `sentenceRule`          | 文分割規則の識別子（`documentType`により異なる）                                            |
| `rateDenominator`       | 句読点レートの分母定義（整形後の文字数、空白込み）                                          |
| `ngramRule`             | n-gram生成規則の識別子                                                                      |
| `tokenizer`             | 使用した解析器と辞書のバージョン文字列。`lindera-wasm-unidic-nodejs:<version>/unidic`の形式 |
| `sentenceEndingRule`    | 文末表現分類の境界規則識別子                                                                |
| `lsmDefinition`         | LSMカテゴリ定義ファイルの参照。`config/lsm_categories.yaml`                                 |
| `lsmClassificationRule` | LSM分類ロジックのバージョン識別子（数量詞・モーダル否定除外を含む版を示す）                 |
| `keigoDefinition`       | 敬語辞書ファイルの参照。`config/keigo_lexicon.yaml`                                         |

お手本媒体・編集対象媒体は常に同じ解析器・同じ定義（`lsmDefinition`・`keigoDefinition`）で計測する。

比較を行う2つの計測（お手本・編集対象）は、`version`・`documentType`・`paragraphRule`・`sentenceRule`・`tokenizer`・`sentenceEndingRule`・`lsmDefinition`・`keigoDefinition`の8項目が一致していることを前提とする。自動照合するのはこの前提のうち`tokenizer`だけで、章単位編集案の`prepare`（`revision.ts prepare`）がお手本プロファイルとそのスコープのスコーププロファイル間で照合する。同じ`prepare`は`lsmClassificationRule`も別途照合する。`build-report.ts`はプロファイルを読んで`comparison_data*.json`を組み立てるだけで、`measurement`の項目照合は行わない。残りの項目（`documentType`・`paragraphRule`・`sentenceRule`・`sentenceEndingRule`・`lsmDefinition`・`keigoDefinition`）と`rateDenominator`・`ngramRule`・`textState`は自動照合しない。

両媒体（お手本・編集対象）のプロファイルは`measurement`に`sanitization`（`version`・`termListHash`・`nonPiiExceptionList`）をさらに持つ。入力整形（用語除去・例外リスト）に使った設定のバージョンとハッシュを記録するもので、比較対象2件の照合には含めない。`version`の現在の値は`basic-pii-and-terms-v1`。

## 再計測の要件

入力整形の用語・PATTERN_LIST・例外、文書の前処理のルール（見出し・区切り線除去、行境界）、文・段落分割規則、トークナイザ契約、LSMカテゴリ定義、モーダル否定除外、文末表現パターン、敬語辞書、長さ分布のパーセンタイル定義のいずれかを変更した場合、お手本媒体・編集対象媒体の両方を同じ定義で再計測する。片方だけを再計測した状態で比較すると、計測メタデータの不一致により比較・判定規則・章単位編集案のいずれも成立しない。

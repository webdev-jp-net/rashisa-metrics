# 開発用ネーミング辞書

## 辞書の位置づけ

このドキュメントは、rashisa-metricsで用いる名称を統一するための辞書です。

## プロジェクト名称

- **日本語名称**: RASHISAメトリクス
- **英字表記スラグ**: `rashisa-metrics`

## 基本原則

- 同一概念には同一名称を使用する
- 表示（日本語）とコード（英語）で対応関係を明確にする
- セマンティックな命名を優先する
- 略語は、この辞書に載せたものだけを使う

## 識別子のケース規則

| 対象                   | 規則                                                                                            | 例                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 変数・関数             | camelCase                                                                                       | `modelLabel`、`computeOverviewCriteria`                     |
| 型・コンポーネント     | PascalCase                                                                                      | `DiffBoxModel`、`ScopePanel`                                |
| 定数                   | UPPER_SNAKE_CASE（モジュール直下のリテラルのみ）                                                | `VIEWPOINT_LIST`、`ABS_LIMIT_LIST`                          |
| ファイル・ディレクトリ | コンポーネントはPascalCaseディレクトリ、libモジュールはkebab-caseの`.ts`、SCSSは`*.module.scss` | `DiffBox/`、`sequence-matcher.ts`、`ScopePanel.module.scss` |

複数形を表す際は、末尾に`s`をつけず接尾辞として`List`を使用する（例: `getReportList`、`reportList`）。

## ドメイン固有用語

「許容別名」は表示や会話で使ってよい言い換え、「禁止表記」は同じものを指すのに使わない語。

### 観点と指標

| 正式日本語 | コード表記  | 定義                                                                                  | 許容別名 | 禁止表記 | 使用例                                                      |
| ---------- | ----------- | ------------------------------------------------------------------------------------- | -------- | -------- | ----------------------------------------------------------- |
| 観点       | `viewpoint` | LSM類似度・文末表現・敬語の密度・文・段落の長さの4分類                                | 「軸」   | -        | `viewpoint: 'lsm' \| 'endings' \| 'politeness' \| 'length'` |
| 指標       | `metric`    | 26指標。`group.item`のpath形式で識別する（例: `lsmCategory.ratioList.caseParticles`） | -        | -        | `metric.path`                                               |
| 群         | `group`     | 指標の分類。文法語・文末・丁寧度・文長・段落長・LSM                                   | -        | -        | `group: '文法語'`                                           |
| 項目       | `item`      | 群内の個別指標名（例: 文法語の「数量詞」、文末の「終助詞止め」）                      | -        | -        | `item: '数量詞'`                                            |

26指標は群ごとに、文法語10（格助詞・係助詞・接続助詞・終助詞・助動詞・接続詞・代名詞・副詞・否定・数量詞）、文末7（です・ます・体言止め等・文末なし・終助詞止め・記号止め・だ・である・絵文字止め）、丁寧度3（丁寧語・尊敬語・謙譲語）、文長3（平均・中央値・90%点）、段落長3（平均・中央値・90%点）で構成する。LSMの平均は群としては別枠で、26指標には含めない。

### テキスト処理

| 正式日本語         | コード表記                           | 定義                                                                                                                                                                                            |
| ------------------ | ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 原稿               | `manuscript`                         | 編集対象媒体の原資料。スコープごとに1ファイル                                                                                                                                                   |
| 原資料             | `source/`                            | 原資料ディレクトリ（お手本・編集対象それぞれの`modelSource`・`editedSource`）の置き場（リポジトリ直下、非追跡）。どの処理も書き込まない                                                         |
| 原資料ディレクトリ | `modelSource` / `editedSource`       | 媒体ごとの原資料の置き場。中身は1文書＝1つの`.md`（お手本1記事1ファイル、編集対象1スコープ1ファイル）                                                                                           |
| 文書               | `document`                           | 原資料ディレクトリ内の1ファイル。お手本では1記事、編集対象では1スコープ。`sourceRef`はファイル名から`.md`を除いた文字列（例：`scope-03`、note記事のキー）                                       |
| 抽出処理           | `extract`                            | 原資料ディレクトリから文体プロファイル・実例集・書き方シート・統合文書を作る一連の処理。CLIは`scripts/extract.ts`（`prepare [--check]`／`verify`）。仕様は[抽出処理](../analysis/extraction.md) |
| スコープ本文       | `chapterSource`                      | 1文書の前処理をした本文                                                                                                                                                                         |
| 匿名化             | `clean`                              | 実名等を除去・置換した計測用テキスト                                                                                                                                                            |
| 表示用マスク       | `visible`                            | 画面表示用に伏せ字・言い換えを施したテキスト                                                                                                                                                    |
| 形態素             | `token`                              | 解析器が分割した最小単位。surface・pos1・pos2・lemma・document（出典文書のindex）を持つ                                                                                                         |
| 見出し語           | `lemma`                              | 形態素の辞書形                                                                                                                                                                                  |
| 品詞               | `pos1` / `pos2`                      | 品詞の第1階層・第2階層（例: 助詞・格助詞）                                                                                                                                                      |
| LSM                | `lsm`                                | Language Style Matching。カテゴリ別の使用比率一致度                                                                                                                                             |
| 文末表現の7分類    | `endingLabelList`                    | です・ます・体言止め等・文末なし・終助詞止め・記号止め・だ・である・絵文字止めの7分類                                                                                                           |
| 敬語3分類          | `sonkeigo` / `kenjougo` / `teineigo` | 尊敬語・謙譲語・丁寧語                                                                                                                                                                          |
| 数量詞             | `quantifiers`                        | `config/lsm_categories.yaml`の辞書に載る程度・数量の語（少し・たくさん・ほど等）。数全般ではない                                                                                                |
| 否定               | `negations`                          | 否定の助動詞・形容詞・接続（ない・ぬ・ず）                                                                                                                                                      |
| 推量構文除外       | `excludeModalConstruction`           | 「かもしれない」等の推量表現末尾の否定助動詞を否定に数えない除外規則                                                                                                                            |
| 分母だけの変化     | `denominatorOnlyChange`              | 分子（出現数）が変わらず分母だけの変化で比率が動くこと。改善とみなさない                                                                                                                        |
| overshoot          | `overshoot`                          | お手本媒体の値を超えて動き過ぎること。採用しない条件の一つ                                                                                                                                      |
| 入力ハッシュ       | `sourceHashList`                     | 原稿・プロファイル・設定ファイル等の入力SHA-256。一致しない場合は工程を停止する                                                                                                                 |
| 英語定型の直訳     | `find-cliche`                        | 英語圏の慣用句・比喩・定型表現に由来すると推定される文の検出（`tools/find-cliche`、結果は`data/<seriesKey>/find-cliche/`）。「英語なまり」も同じものを指す                                      |

## ルーティング

ハッシュ一覧は[ルーティング仕様](../spec/frontend/routing.md#ハッシュフラグメント)を参照。識別子の命名規則はスコープパネルが`report-{key}`、対応するタブが`tab-report-{key}`。`/`が閲覧できるシリーズの一覧、`/<seriesKey>/`がそのシリーズのレポートで、許可リスト判定（[NextAuth認証仕様](../spec/backend/next-auth.md)参照）を行う。`/api/auth/*`にNextAuthの認証API Routeを持つ。

## JSON型・config型のキー名規則

- `data/`配下のJSONファイルは`src/lib/data`で型を付けて読み込む
- `data/`・`config/`配下のJSON・YAMLのキーはcamelCase（例: `displayReason`、`sourceHashList`）でそのままTypeScriptの識別子と対応する。ファイル上もTypeScript側もcamelCaseで揃える
